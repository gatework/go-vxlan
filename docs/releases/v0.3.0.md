# v0.3.0

本版本深化 Fabric 核查与执行状态的职责边界，包含公开 Go API 调整；CLI 参数、证据 JSON、精确数值、来源顺序及计划指纹保持兼容。

- `ReviewFabric` 增加查询目录参数；`QueryCatalog` 增加 `VerificationCommands(scope)`。传入选定 Profile，或让自定义目录提供该能力。`ProfileSpec.Verification` 声明 Fabric 核查序列，缺失时保留诊断但不生成可执行候选。
- NX-OS 保留原来的配置、VNI、各 VRF IP 接口三条核查命令；不把普通接口采集查询当作等价替代。
- 适配器使用 Connector 的唯一接受回执与严格正文 API，保留 accepted Capture 与晚错误、原始 Attempts 及既有提示符换行边界。
- 配置和环境文件使用有界共享读取与严格根映射解析，贯通 context；运行库存、筛选、凭据和策略冻结，诊断 map 的修改不影响执行。
- apply 使用私有类型化状态，每次日志投影取得独立数据；已确认步骤、提交后失败和 uncertain 语义保持，不自动重放、回滚或保存。
- 一次网关审查复用相同上下文及 VRF 冲突查询。固定 64 设备夹具耗时约降 47%，分配约降 46%；小规模权衡与复现见 [基准说明](../benchmarks.md)，不代表设备吞吐。

固定正式 Connector v0.5.0、Expect v0.4.2；构建使用 GOWORK=off，无本地依赖副本或 replace。旧依赖目录和已失效实施记录移除，AGENTS、架构、迁移与验证说明随源码维护。

完整迁移见 [API 说明](../api-migration.md)。发行包复用同提交 CI 产物，覆盖 Linux/macOS × amd64/arm64，附许可与 SHA256SUMS；未以 CI 代替生产设备验收。
